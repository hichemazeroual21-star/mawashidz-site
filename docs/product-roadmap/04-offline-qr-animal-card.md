# 4 — بطاقة الحيوان وQR دون إنترنت

## قرار الحالة أولًا

| النموذج | الحالة |
|---|---|
| QR بمعرف مبهم يفتح API وصفحة تحقق إلكترونية | **معتمد** — قرار D-006 |
| عرض آخر نسخة مخزنة مع وسم «قديمة» | **معتمد كاتجاه** — مرحلة 6 |
| تضمين بطاقة مختصرة موقعة داخل QR للتحقق offline | **مقترح** — يحتاج ADR/Decision Log وموافقة المؤسس |
| هوية رسمية/جواز صحي/تتبع حكومي | **ممنوع ادعاؤه** دون تفويض رسمي مكتوب |

المطلب «امسح ويظهر كل شيء دون إنترنت» له حدود تقنية يجب قولها بوضوح:

| حالة الهاتف | الممكن |
|---|---|
| كاميرا النظام، لا إنترنت | قد تعرض الرابط أو النص الخام حسب الهاتف؛ لا تحقق توقيع ولا واجهة MawashiDZ مضمونة |
| PWA مثبت فقط | التثبيت وحده لا يكفي؛ يجب أن يكون Service Worker مسيطرًا وأن تكون shell والمفاتيح والمسار مخزنة |
| ماسح MawashiDZ داخل PWA مخزن مسبقًا | شاشة كاملة + تحقق توقيع ومعلومات مضمنة/مخزنة، إذا اعتُمد النموذج الموقّع |
| متصل بالإنترنت | التحقق من الحالة الحالية، الإلغاء، النقل، والصورة والسجل المسموح |

لا يمكن لموقع ويب لم يسبق تحميله أن يظهر واجهته كاملة بلا شبكة. لذلك التجربة
المهنية المقترحة هي **ماسح داخل PWA** مع Service Worker ونطاق وروابط مختبرة على
كل نظام تشغيل. فتح رابط `https` من كاميرا النظام في وضع الطيران ليس مسارًا
مضمونًا، حتى لو كان التطبيق مثبتًا.

لضمان فائدة أساسية لأي شخص بلا تطبيق أو شبكة، يجب أن تكون **البطاقة المطبوعة
ثنائية الطبقة**:

1. نص بشري قصير بجوار QR: معرف MawashiDZ، النوع، سنة الميلاد التقريبية، وعلامة
   بصرية.
2. QR للتفاصيل والتحقق الإلكتروني أو الموقّع المقترح.

بهذا لا يصبح QR نقطة فشل وحيدة، ولا ندعي أن كل كاميرا هاتف توفر تجربة تطبيق
offline.

## التصميم المعتمد للنسخة الأولى

```text
QR → معرف عام مبهم → API محدود ومقاوم للإساءة → بطاقة الحيوان العامة
```

مثال:

```text
https://mawashidz.com/q/a/7M4K9P2X
```

لا يحتوي المعرف:

- UUID قاعدة البيانات.
- اسم أو هاتف المالك.
- رقم هوية وطنية.
- موقع المزرعة.
- معلومات صحية حساسة.

## المقترح: بطاقة موقعة داخل الرابط

إذا أُقرّ التعديل المعماري، يمكن أن يحمل fragment بيانات قصيرة موقعة:

```text
https://mawashidz.com/q/a/{opaque_id}#c={signed_compact_card}
```

الـfragment لا يُرسل تلقائيًا إلى الخادم. تطبيق MawashiDZ يفك البطاقة ويتحقق من
التوقيع بمفتاح عام مخزن. التقنية الدقيقة — مثل CBOR + COSE/Ed25519 — تُحسم في ADR
بعد اختبار حجم QR ودعم الهواتف؛ ليست قرارًا في هذا الدليل.

الـfragment ليس سريًا: تستطيع سكربتات الصفحة وقارئ QR والمستخدم الذي يشارك الرابط
قراءته، وقد يبقى في السجل أو النسخ أو لقطات الشاشة. لذلك لا تدخل الحمولة أي معلومة
لا يجوز طباعتها علنًا. حماية API من الكشط لا تحمي الحقول المضمنة داخل الرمز.

## أقل حمولة ممكنة

| المفتاح المنطقي | الغرض |
|---|---|
| `version` | إصدار مخطط البطاقة |
| `issuer` | مساحة إصدار MawashiDZ غير الحكومية |
| `key_id` | اختيار مفتاح التحقق العام ودعم التدوير |
| `card_id` | معرف هذه النسخة من البطاقة |
| `animal_id` | معرف الحيوان العام المبهم |
| `issued_at` | تاريخ الإصدار |
| `recheck_after` | حد زمني لعرض «قديمة — تحقق إلكترونيًا»؛ ليس انتهاء صلاحية أو إثبات عدم الإلغاء |
| `assurance` | تصريح ذاتي / وثيقة مراجعة / مشاهدة ميدانية |
| `species` | النوع |
| `sex` | اختياري |
| `birth_precision` | مجهول / سنة / شهر / تاريخ |
| `birth_value` | القيمة بحسب الدقة |
| `visual_traits` | لون/سلالة/علامات مختصرة |

لا تتضمن النسخة المقترحة `record_digest` افتراضيًا: أي بصمة ثابتة بجوار
`animal_id` قابلة للربط بين عمليات المسح. إضافتها تحتاج ADR وسببًا مثبتًا ومراجعة
خصوصية.

## ما يثبته التوقيع وما لا يثبته

يجب عرض ثلاث حالات منفصلة، لا حالة «صالحة» مبهمة:

| الحالة | معناها offline |
|---|---|
| أصالة التوقيع | الحمولة صدرت من مفتاح عام معروف ولم تتغير |
| القِدم | وقت الجهاز تجاوز `recheck_after` أو لا يمكن الوثوق بساعة الجهاز |
| الحالة الحية | **غير معروفة offline**: الإلغاء والنقل والتصحيح تحتاج اتصالًا |

### يثبت

- أن الحمولة صدرت بمفتاح MawashiDZ.
- أن البيانات الموقعة لم تتغير بعد الإصدار.
- تاريخ الإصدار ومستوى التأكيد المعلن.

### لا يثبت

- أن الملصق لم يُنسخ أو يُنقل إلى حيوان آخر.
- أن الحيوان لم يُبع أو يمت أو تُلغَ بطاقته بعد الإصدار.
- أن مفتاح التوقيع لم يُلغَ بعد آخر تحديث لقائمة المفاتيح المخزنة.
- أن السلالة أو العمر أو الصحة أكّدتها جهة رسمية.
- الملكية القانونية.
- صلاحية نقل الحيوان أو ذبحه أو دعمه.

## التهديدات والضوابط

| الخطر | الضابط |
|---|---|
| نسخ QR | صورة وعلامات بصرية + زر إبلاغ + تحقق إلكتروني |
| نقل الملصق | مقارنة الحيوان الظاهر + إعادة إصدار/إلغاء |
| إعادة استخدام بطاقة قديمة | `recheck_after` + حالة stale + قائمة إلغاء عند الاتصال |
| كشط المعرفات | معرفات عشوائية + rate limiting + أقل بيانات |
| تسرب بيانات المالك | منع PII من الحمولة العامة |
| سرقة مفتاح التوقيع | المفتاح الخاص على الخادم فقط + `key_id` + تدوير وإلغاء |
| التعديل offline | ممنوع؛ كل تغيير يحتاج الخادم، وإذا اعتُمد النموذج الموقّع تُصدر بطاقة جديدة |

يجب أن يحمل مخزن المفاتيح العامة تاريخ آخر مزامنة، وأن يعرض التطبيق «حالة المفتاح
غير معروفة» إذا انتهت مدة الثقة أو كانت ساعة الجهاز غير موثوقة. لا توجد طريقة
لمعرفة إلغاء بطاقة أو مفتاح جديد أثناء انقطاع كامل.

## دورة البطاقة

```text
إنشاء الحيوان
  → إصدار بطاقة
  → طباعة/ربط QR
  → مسح وتحقق
  → تغيير جوهري أو نقل ملكية
  → إلغاء card_id القديم
  → إصدار بطاقة جديدة
```

لا يتغير تاريخ الحيوان عند إعادة إصدار البطاقة. البطاقة نسخة قابلة للإلغاء؛ سجل
الملكية والأحداث يبقى منفصلًا ومدققًا.
